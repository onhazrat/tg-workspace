# SET-04: Configuration rows

**What to build:** An Operator holding `settings:manage` sees, on the same
page, everything the deployment is tuned by that is not a Setting:

- every `.env` value the backend reads, with its comment, source (environment,
  `.env`, code default), value and "Restart to apply"
- every frontend build value, with the value this browser runs and "Rebuild to
  apply"
- every tuning constant in the code, with its comment, file:line and "Needs a
  deploy"

The rows are grouped under their topics, hidden behind "Show N" until searched
for or chosen in the contents. They can be found with `@scope:env`,
`@scope:code` and `@restart`. Secrets only ever show "set" or "not set". A
`.env` value that differs from the code's default counts as changed; a secret
never does. Accounts without the Permission see none of it.

Spec: `.scratch/settings-one-page/spec.md` (stories 8, 31, 47–51; the
Configuration rows and secrets decisions). Plan decisions 3, 5, 6, 19, 21, 27.
Reference implementation: the prototype API's `.env` and constants scanning on
branch `prototype/settings-one-page`. It scanned the frontend live, which
cannot work in the backend image; here a generated catalog replaces that.

**Blocked by:** SET-02

**Status:** ready-for-agent

- [ ] `.env` rows are generated from the backend's settings class (type, comment) with values and sources from the running process; frontend build values from the env manifest with values reported by the running bundle.
- [ ] Code constants come from a generated catalog of every module-level numeric or boolean UPPER_CASE constant in backend and frontend source (value, expression, comment, file:line), regenerated by a pre-commit hook beside the env catalog's. A guard fails when the catalog is stale.
- [ ] Each constant's topic comes from an explicit module → topic map; a guard fails when a module with a constant has no topic. A short exclusion list drops unit conversions.
- [ ] Secrets carry only "set" / "not set" in the registry response itself, never their value, and are never "changed"; asserted at the route seam.
- [ ] Configuration is invisible to an Account without `settings:manage`; asserted at the route seam with two Accounts.
- [ ] `@restart` and `@scope:env|code` work; the contents tree's changed counts include Configuration by the rule above.
- [ ] Deleted: the old admin configuration catalog route and its view.
- [ ] The new guards are mutation-tested; the env-example and CI path-filter guards still pass.
